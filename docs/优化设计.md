# gei-world 优化设计

本文是当前唯一的开发路线文档，取代原 `后续执行计划.md` 与 `多人联机与回合模式规划.md`（历史进展可在 git 记录中查看）。

> 状态：第 1~6 节为优化前的评估与计划，A~G 七个阶段已全部执行，结果见文末「7. 执行结果」。

## 1. 现状评估

项目规模：`src` 约 2.9k 行、`ui` 约 2.8k 行、`tests` 约 3.3k 行、`scripts` 约 1.3k 行。

已具备：

- 六边形地图、陆地/海洋、战争迷雾、移民建城、城市生产、士兵栈、战斗/攻城、胜负判定。
- 轮流 / 同时两种回合模式；单人对 AI、本机多人、HTTP 多人（服务端权威）。
- 存档多槽位、结构化行动结果、PyInstaller 打包与 GitHub Release 流程。

结论：**功能骨架完整，但"像一个游戏"的部分很薄**——数值没有平衡、地图是噪点、AI 基本随机、UI 是调试界面风格、多人是原型级别。下面按问题域列出证据和改法。

## 2. 主要问题

### 2.1 数值与规则（影响最大）

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| 经济数值失衡 | `src/config.py`：初始金币 100、士兵 1 金币、移民 50 金币 | 首回合即可爆 50 个士兵，没有经营取舍 |
| 城市防御是常量 | `CITY_CONFIG["defense_value"] = 2`，`combat_system.attack_city` 不看驻军以外因素 | 2 个士兵即可攻城，攻防无深度 |
| 城市生产无上限 | `city_system.build_unit` 无每回合次数限制（需求文档要求每回合 1 次） | 金币 = 瞬时兵力 |
| 士兵无法消灭移民 | `combat_system.resolve_combat` 任一方无士兵时直接返回，敌方移民与士兵可同格共存 | 规则漏洞 |
| 占领与收入脱节 | 士兵可占领任意陆地，但收入只计城市经济半径 2 内的己方地块 | 远端占领没有意义，玩家困惑 |
| `production_queue` 是死字段 | 只有存档读写，没有任何逻辑使用 | 误导 |

### 2.2 地图生成

所谓 `PerlinNoiseMapGenerator` 实际是逐格独立随机，没有空间相关性。实测 5 个种子：陆地约 40%，**14~25 个陆地连通块，其中 6~14 个是单格孤岛**，最大陆块 45~107 格。`MAP_CONFIG["ocean_ratio"]=0.3` 与公式叠加后实际海洋约 60%，配置失真。`IslandMapGenerator` 只在测试中使用。生成器调用全局 `random.seed`，会污染 AI 和出生点的随机状态。

### 2.3 AI

UI 默认使用 `SimpleAI`：能建城、能造兵，但移动目标是 `random.choice(reachable_tiles)`，基本不构成威胁。较好的 `AggressiveAI`（集结、按兵力攻城）没有接入 UI。AI 没有扩张选址、没有防守意识、没有阶段策略。

### 2.4 架构

- `ui/client_controller.py` 1550 行，混合了：主菜单、单机 AI 回合调度、本机/HTTP 多人房间流程、输入处理、选择逻辑、渲染调度、存档弹窗。
- 单位状态三份存储：`tile.units`、`player.units`、`unit_system.units`，靠 `_sync_unit_registry` 事后修补；城市同理（`tile.city`、`player.cities`、`city_system.cities`）。
- 行动事件靠"行动前后快照 diff"反推（`game_engine._capture_action_snapshot`），而不是在规则执行处直接产出，容易漏事件。
- 死代码：`unit_system` 中 `_find_land_path_distance`、`_can_reach_ocean_as_final_step`、`_can_reach_with_any_terrain`、`get_unit_vision_tiles`；`vision_system.has_line_of_sight`；`player_system.current_player_index/next_player`；`src/utils.py` 只被旧脚本和旧测试引用。

### 2.5 性能

- **HTTP 多人每帧 2 次网络请求**：`_render → _get_game_state → _get_multiplayer_status` 每帧调用 `get_room_state` + `get_player_view`，60 FPS 即每秒 120 次请求；且每次刷新视图都会让 `HTTPNetworkSession` 丢弃并重建整份引擎镜像。
- `render_system._draw_unit_marker` 每个单位每帧 `pygame.font.Font(None, ...)` 新建字体。
- `get_reachable_tiles` 对全图每一格单独 BFS（实测约 3 ms/次），AI 每个动作都会调用；地图变大后会成为瓶颈，应改为一次 BFS 求可达集。

### 2.6 UI / UX

- 开始界面是键盘提示文字列表（`SPACE/T/M/H/L`），没有按钮、没有新游戏设置（玩家数、AI 难度、地图类型、种子、回合模式）。
- 调试流程暴露给玩家：HTTP 弹窗里的"创建调试房"（一个客户端同时占两个席位）、多人 `TAB` 切换席位、`client_1` 这类内部 ID 需要玩家手抄。
- 右侧信息面板固定 430 高，挤满玩家信息/多人状态/选择详情/操作说明，多人事件被截断为 `message[:14]`。
- 视觉：纯色六边形 + 菱形城市 + 圆点士兵，无地形纹理、无边界线、无回合过渡、无战斗反馈动画。
- 硬编码像素坐标遍布 `ui_system`（按钮 `Rect(10, 50, 100, 30)` 等），窗口不可缩放。

### 2.7 多人安全与稳定性

- `ThreadingHTTPServer` 并发处理请求，但 `MultiplayerServer` 没有任何锁，同时提交行动存在竞态。
- `room_1` / `client_1` 顺序可猜，知道地址即可冒充任何玩家；没有房间密码或 token。
- 无心跳/超时：玩家断线不退出时，同时回合会永远等待。

### 2.8 工程

- 脚本冗余：`scripts/demo.py`、`enhanced_demo.py`、`interactive_game.py` 是早期命令行演示，`ui_demo.py` 只是打印说明后启动 `ui_game.py`，均无被构建/测试引用。
- 测试风格不统一：`test_hex_tiling.py`、`test_territory_vision.py`、`test_ui.py`、`test_enhanced_features.py` 大量 `print`、断言稀少；`test_improvements.py` 主要测 `utils.py`。
- `ui/`、`scripts/` 里多处 `sys.path.insert` 手动改路径，没有包结构/入口点。

## 3. 优化目标

一句话：**从"功能原型"变成"一局 20~40 分钟、有取舍、能和朋友联机的小型 4X"**。

验收口径：

1. 新玩家不看文档能开一局并理解目标。
2. 一局中存在"扩张 vs 军备 vs 防守"的真实取舍。
3. AI 能在简单难度下完成扩张并主动进攻。
4. 两人通过 Tailscale 联机可完整打完一局，无卡死、无冒充。

## 4. 路线（按顺序执行，每阶段可独立提交）

### 阶段 A：清理与关键缺陷（约 1~2 天）

- 删除过时文档（本次已完成）。
- 删除或归档 `demo.py`、`enhanced_demo.py`、`interactive_game.py`、`ui_demo.py`；`src/utils.py` 和依赖它的旧测试一并清理。
- 删除 2.4 中列出的死代码与 `production_queue`（存档兼容读取保留忽略逻辑）。
- 修复士兵无法消灭/俘获敌方移民。
- `MultiplayerServer` 加 `threading.RLock`，所有公开方法加锁。
- 多人状态轮询改为节流：房间状态与视图每 0.5~1 秒拉一次，或仅在 `recent_events` 序号变化时刷新视图；镜像引擎只在视图版本变化时重建。
- 字体对象缓存到 `FontManager`。
- 地图生成改用独立 `random.Random(seed)` 实例，不再污染全局随机状态。

验收：全量测试通过；HTTP 多人空闲时请求频率 ≤ 2 次/秒。

### 阶段 B：规则与数值重做（约 2~3 天）

建议初始数值（需通过阶段 D 的 AI 对战模拟再调）：

| 项 | 现值 | 建议 |
| --- | --- | --- |
| 初始金币 | 100 | 20 |
| 移民成本 | 50 | 30，且建造后城市本回合不能再生产 |
| 士兵成本 | 1 | 5 |
| 收入 | 经济半径内己方地块 × 1 | 城市中心 +3，经济半径内己方陆地 +1 |
| 城市防御 | 常量 2 | 基础 3 + 每回合 +1（上限 8），被攻破后归零 |
| 生产限制 | 无 | 每城每回合 1 次生产行动（士兵可批量但受金币约束） |
| 占领规则 | 任意陆地 | 只能占领与己方领土相邻的地块；经济半径外占领只提供视野 |

规则变更同时：

- 新增 `src/rules.py`（或扩展 `config.py`）集中定义数值，UI 文案从规则读取。
- 补齐胜利条件：消灭对手 / 占领全部敌方城市 / 回合上限时按分数（城市、领土、兵力）判胜。

验收：新增规则测试；AI 对 AI 100 局模拟中先手胜率在 40%~60%。

### 阶段 C：地图生成（约 1~2 天）

- 用分形值噪声（多倍频叠加）或"种子扩张 + 平滑"生成大陆，按目标陆地比例取阈值，保证 `ocean_ratio` 真实生效。
- 后处理：去掉 1~2 格孤岛，保证每个出生点所在陆块 ≥ 25 格。
- 出生点公平：按"可建城面积 + 到其他出生点距离"打分选取。
- 新增地图类型参数：大陆 / 群岛 / 盘古；地图半径 8 / 10 / 14。
- 可选：新增丘陵/森林地形（移动消耗 2、防御加成），为玩法提供地形取舍。

验收：100 个种子中孤岛（≤2 格）数为 0，最大陆块占陆地 ≥ 60%（大陆模式）。

### 阶段 D：AI 重写（约 3~4 天）

- 改为效用评估：每个候选行动打分（建城选址分、生产需求分、威胁分、攻城胜算分），取最高分。
- 阶段策略：开局扩张（2~3 城）→ 经济与防守 → 兵力优势时集结攻城。
- 防守：敌军进入城市 2 格内时优先回防或造兵。
- 难度：简单 = 决策加噪声；普通 = 完整评估；困难 = 少量资源加成。
- 新增 `scripts/simulate.py`：AI 对 AI 批量对战，输出胜率、平均回合数，用于阶段 B 调参。

验收：普通 AI 在 30 回合内平均拥有 ≥ 3 城，并能主动攻下守备不足的玩家城市。

### 阶段 E：UI/UX 重做（约 4~6 天）

- 主菜单：按钮化（单人游戏 / 多人游戏 / 读取存档 / 退出）。
- 新游戏设置页：玩家数（2~4）、每个席位人类/AI 及难度、回合模式、地图类型与大小、种子。
- 多人页：只保留"创建房间 / 加入房间 / 重新连接"；房间码改为 6 位短码，自动记住本机客户端身份（存本地配置文件），不再让玩家手抄 `client_id`；"调试房"和 `TAB` 切席位仅在开发模式（环境变量）开启。
- HUD 重排：顶部资源条（回合、模式、金币、收入、城市/兵力）；右侧上下文面板（选中对象）；左下事件日志（可滚动，不截断）；多人席位状态单独小卡片。
- 布局常量化：所有坐标基于屏幕尺寸计算，支持窗口缩放。
- 视觉：地形配色与描边、领土边界线（只画国境而非整格染色）、城市/士兵图标、回合开始横幅、战斗结果浮字。
- 操作：快捷键提示面板（`F1`）、下一个可行动单位（`N`）、结束回合确认保留。

验收：新玩家在无文档情况下完成"开局 → 建城 → 生产 → 攻城"流程。

### 阶段 F：架构整理（与 E 并行，约 3~4 天）

- 拆分 `client_controller.py`：
  - `ui/app.py`：主循环与场景切换。
  - `ui/scenes/menu_scene.py`、`new_game_scene.py`、`multiplayer_scene.py`、`game_scene.py`。
  - `ui/controllers/selection_controller.py`（选择/移动/建城输入）。
  - `ui/controllers/turn_controller.py`（结束回合、AI 调度）。
  - `ui/controllers/multiplayer_controller.py`（房间流程、轮询节流）。
- 单一状态源：`unit_system` / `city_system` 用 `dict[id, obj]` 作为唯一注册表，`tile.units`、`player.units` 改为派生查询或统一由一个 `WorldState` 维护增删，消除 `_sync_unit_registry`。
- 事件由规则直接产出：`move/attack/capture/build` 各自返回事件列表，删除快照 diff。
- 项目改为可安装包结构（`pyproject.toml` + 入口点 `gei-world`），去掉各处 `sys.path.insert`。

验收：`client_controller.py` 不再存在或 < 300 行；测试全部通过。

### 阶段 G：多人产品化（约 3~5 天）

- 加入房间返回随机 `session_token`，所有写操作校验 token；房间可设密码。
- 心跳：客户端每 5 秒上报，超过 60 秒未响应标记离线；同时回合可配置"离线玩家视为已结束"或房主强制推进。
- 关闭房间定期清理；服务端日志。
- 可选：轮询改长轮询或 WebSocket，降低延迟与请求量。
- 多人存档：服务端可保存/恢复房间快照。

验收：两台电脑经 Tailscale 完整打完一局；伪造 `client_id` 的请求被拒绝；一方断线 60 秒后另一方可继续。

## 6. 推荐执行顺序

```text
A 清理与关键缺陷 → B 规则数值 → C 地图 → D AI（含模拟调参，回头微调 B）
→ F 架构拆分 → E UI 重做 → G 多人产品化
```

先做 A~D 的理由：玩法好不好玩取决于数值、地图和 AI，UI 再漂亮也掩盖不了"一回合爆 50 个兵"。F 放在 E 前面是为了在新 UI 落地前把 1550 行控制器拆开，避免在旧结构上继续堆代码。

总工作量估计：约 17~26 个开发日。

## 7. 执行结果

全部阶段已按 A → B → C → D → F → E → G 顺序完成并分阶段提交。测试从 104 个增至 159 个，`ruff check` 全部通过。

### 阶段 A：清理与关键缺陷

- 删除 4 个旧演示脚本、`src/utils.py` 及其测试；删除 `production_queue` 与各系统中未使用的方法。
- 修复：士兵可消灭无保护的敌方移民；战败方地块上的单位全部清除（不再残留幽灵单位）；移民不能进入敌方格；任何单位都不能穿过敌方单位/城市。
- 多人服务端加 `RLock`；HTTP 状态轮询节流（空闲时约 2 次/秒），视图未变时复用引擎镜像；字体缓存；地图使用独立随机源。
- 可达范围改为单次 BFS。

### 阶段 B：规则与数值

- 初始金币 20、移民 30、士兵 5；收入 = 城市中心 3 + 经济范围内己方陆地 × 1。
- 城市防御初始 3、每回合 +1、上限 8，被攻下后归零；攻城失败会按进攻兵力削减防御。
- 每城每回合 1 次生产；领土只能与己方领土相邻扩张。
- 淘汰：无城市且无移民（残余士兵撤出地图）；100 回合未分胜负按分数（城市、领土、士兵）判胜。
- 轮流回合的收入/移动力/防御结算改在各玩家自己回合开始时进行，消除先后手的结算时机差。

### 阶段 C：地图

- 分形值噪声 + 径向衰减；大陆模式另加分散的大陆核心并沿 Voronoi 边界开凿海峡。
- 后处理去除 1~2 格孤岛、填平小湖；出生点按陆块大小、周边可建城面积、间距与公平性多次寻优，并随机分配席位。
- 100 个种子统计：三种地图均无 ≤2 格孤岛；大陆模式平均 2.3 块主要大陆；盘古模式最大陆块平均占 99%；4 人局出生点最小间距 ≥4。

### 阶段 D：AI

- 效用评分 AI：移民选址、按威胁/扩张/军备决定生产、士兵按攻城 > 消灭弱敌 > 回防 > 集结进攻 > 扩张领土 > 探索的优先级行动；只使用本方可见信息。
- 三档难度：简单（目标 2 城、决策噪声、40% 放弃进攻）、普通（3 城）、困难（4 城、每回合 +2 金币）。
- 新增 `scripts/simulate.py` AI 对战模拟：

| 指标 | 结果 |
| --- | --- |
| 轮流回合先手胜率（100 局） | 56% |
| 同时回合先手胜率（100 局） | 49% |
| 平均对局长度 | 约 53 回合 |
| 第 30 回合平均城市数（简单 / 普通 / 困难） | 2.1 / 3.3 / 4.2 |
| 普通 vs 简单（40 局） | 32 : 8 |
| 困难 vs 普通（40 局） | 33 : 7 |

### 阶段 F：架构

- 单位注册表改为字典且为唯一增删入口，战斗通过单位系统移除单位并回调上报，删除 `_sync_unit_registry`。
- 规则执行时直接产出事件（新增 `siege_failed`、`player_eliminated`），删除前后快照比对。
- `client_controller.py` 由 1550 行拆为主类（279 行）与 6 个职责模块（菜单、反馈、对局流程、地图交互、存档、多人）。
- 新增 `pyproject.toml`（入口 `gei-world` / `gei-world-server`、ruff 配置）、`python -m ui`、CI 工作流；库代码去掉 `sys.path` 注入；旧的打印式测试按领域重写。

### 阶段 E：UI/UX

- 按钮式主菜单；新游戏设置（玩家数、热座人数、电脑难度、回合模式、地图类型/尺寸、种子）；轮流与同时两种热座。
- HUD：顶部资源条、右侧上下文/城市面板（停靠）、多人卡片、可翻页事件日志、回合横幅、战斗浮字、`F1` 快捷键帮助；窗口可缩放，布局按屏幕尺寸计算。
- 地图：地形噪声配色与海岸、领土染色 + 国境线、城堡/盾牌/房屋图标与城市防御徽标、小地图点击跳转。
- 快捷操作：`N` 下一个可动单位、`Enter` 结束回合、默认整栈移动。
- 多人入口：创建房间进入等待大厅、对手加入后自动开局；按房间码加入；本机记住身份，重连无需抄写 ID；调试入口仅在 `GEI_WORLD_DEV=1` 时显示。

### 阶段 G：多人产品化

- 6 位房间码 + 随机身份令牌；公开房间状态不含任何令牌，只公开回合/房间级事件且去掉坐标，避免绕过战争迷雾；可选房间密码。
- 心跳：任何带令牌的请求即心跳，60 秒无请求判定离线；离线玩家轮到行动时自动跳过，房主可 `F` 强制跳过；掉线玩家再次请求自动恢复在线。
- 已关闭/结束房间 10 分钟后清理，无人在线或未开局 30 分钟后关闭；服务端输出房间生命周期日志。
- 房间快照：房主保存到服务端得到恢复码，恢复后其他玩家按原名字认领席位。

### 未纳入本轮的可选项

- 长轮询 / WebSocket（当前轮询已节流，回合制下延迟可接受）。
