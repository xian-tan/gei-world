## 2. 总体推进原则

短期目标不是继续堆新单位、科技树或网络多人，而是先把基础闭环做扎实：

1. 引擎规则可信
2. 战斗/攻城结果可解释
3. 存档可继续游玩
4. UI 流程完整
5. AI/地图/移动逐步提升

每一轮改动都应满足：

- 先补或同步补测试
- 只做一个明确主题
- 使用 `.conda` 环境运行测试
- 通过后再提交
- commit message 使用裸类型前缀，例如 `fix:` / `feat:` / `chore:`，不加 scope 括号

### 优先级 1：引擎规则硬化（已完成第一轮）

这是下一步最优先事项。原因是 UI、AI、存档都依赖 `GameEngine` 的规则权威性。

当前状态：已完成第一轮硬化，覆盖归属校验、敌方地块/敌方城市核心范围建城限制、移动/战斗/攻城后即时胜负检查。

当前风险：

- `execute_action()` 只校验 `action.player_id` 是否是当前玩家
- 具体单位、城市对象的归属校验还不够严格
- 理论上可以构造非法 action 操作别人的单位或城市

建议补测试并修复：

- 非当前玩家不能行动
- 当前玩家不能移动别人的单位
- 当前玩家不能用别人的移民建城
- 当前玩家不能用别人的城市生产单位
- 建城不能建在敌方地块上
- 建城不能建在敌方城市核心范围内
- 战斗/攻城后统一检查胜负状态

主要文件：

- `src/game_engine.py`
- `src/systems/city_system.py`
- `tests/test_gameplay_rules.py`

验收标准：

- 新增非法行动回归测试
